人类终端界面（真实渲染效果）

永不超时的等待循环

AgentDock 对单次 MCP 调用有 300s 上限，所以等待被切成 keepalive 片段：等待本身无限持续，返回只是“续签”。

Agent MCP 服务端（无限等待） 人类终端 │ │ │ │ human_notify(kind="done", then_wait=true) │ │ ├─────────────────────────────────────────►│ 落盘 + 广播 message 事件 ─────────►│ 🔔 响起，显示结果 │ │ │ │ human_wait(keepalive_seconds=240) │ │ ├─────────────────────────────────────────►│ state=waiting │ 等待中 00:02 │ ◄── 每 15s 心跳 notifications/progress ──► │ │ │ │ │ ◄── 240s：status="keepalive" ─────────── │ │ 立刻再次调用 human_wait（不是超时，不许结束对话） │ ├─────────────────────────────────────────►│ │ │ ◄── 人类说话：立刻返回 human_message ──── │ 🧑 提问已发送 │ 回答问题 ─► 再次 human_wait … 无限循环，直到人类说“结束” │ ▼ ▼ ▼
消息永不丢失
消息落盘到 ~/.humanchat/sessions/*.jsonl，只有被 Agent 取走才算“已消费”。 断线、被取消、进程重启之后，下一次 human_wait 会立刻取回。
规则被反复强调
禁止内置提问工具、禁止自行结束对话、keepalive 必须续等 —— 出现在 instructions、工具描述、以及每一次工具返回内容的尾部。
零依赖 & 免安装
纯 Python 标准库实现 MCP（stdio + streamable HTTP）， 在 AgentDock 所在机器上 python3 humanchat_mcp.py 直接可用。
